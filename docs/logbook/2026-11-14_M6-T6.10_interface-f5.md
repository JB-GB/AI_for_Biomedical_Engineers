## Scope
F5 has two parts. Only the part that needs no participants is done here:

  SUS form, scoring).
- **Still to run with people:** the NVDA / Accessibility Insights walkthrough and the SUS sessions. The

## Actions
- **Automated audit** (`python scripts/a11y_audit.py --images GS PD`). It walks every tab, in both themes
  and at the 5 text sizes, before and after an analysis, and checks:
  - **name:** every control has an accessible name;
  - **keyboard:** every control can be reached with Tab;
  - **target:** controls ≥ 44 px (WCAG 2.2 AA asks 24 px);
  - **contrast:** style-sheet text ≥ 4.5:1, focus frames ≥ 3:1;
  - **scaled:** every text control doubles at 200 %;
  - **clipped:** no text cut off at 200 %;
  - **fits:** the window fits a 1366 × 768 laptop (1366 × 728 without the taskbar), with vertical
    scrolling only.

  It writes a Markdown report and exits 1 on any error, so it can run before each session or in CI.
- **Study log** (`rausnet-desktop --study P01`):
  - one JSON line per click, counted key (Tab, Enter, Space, Esc, shortcuts) and drop;
  - a goal event when each task finishes (`analyzed`, `pdf_exported`, `correction_sent`, `undone`,
    `colab_opened`, `model_adopted`, plus `local_started` and `rolled_back`);
  - the facilitator's `Ctrl+Shift+N` task mark.

  It never logs file names, typed text or patient data, and participant codes that look like names are
  refused. The window title shows that logging is on.
- **Scoring** (`scripts/usability_report.py`): SUS per participant and mean with a 95 % t interval
  (built-in t table, no SciPy). Per task: completion, median actions against the budget, median time.
  Exit code 0 only when the acceptance is met.
- **Protocol** (`docs/07_usability_protocol.md`): participants (≥ 3, target 5, non-technical),
  synthetic images only, workspace setup that makes the "adopt new model" task reproducible (rollback
  CLI), 6 task cards with budgets, facilitator script, Spanish SUS, analysis, and the manual NVDA /
  Accessibility Insights checklist with a findings table.

## Decision
- The audit reads controls at the widget level and uses the platform fonts. In CI (Linux, offscreen) the
  name, keyboard, target and contrast checks run; the size checks (fits, clipped) run only under the real
  Windows platform, because offscreen fonts are wider.
- The study log filters events at the widget level and ignores propagated copies by timestamp, so real
  clicks and test clicks count the same and each click counts once. Shortcuts are logged where they
  fire, because they never reach widgets as key presses.
