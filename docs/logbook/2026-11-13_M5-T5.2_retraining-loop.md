# [2026-11-13] M5 — Retraining loop with promotion rule

- **Author:** JB-GB
- **Type:** Result
- **Related:** `src/rausnet/retrain.py`, `registry.py`, `data/merge.py`, `evaluate.py`,
  `configs/retrain/default.yaml`

## Context
The model must be easy to retrain when hospital data or clinician corrections arrive,
without ever silently replacing a better model.

## Actions
- **Merge (T5.1):** source manifests (paths relative to their folder) are rebased onto the data
  root and merged into an immutable dataset version `datasets/<version>/manifest.csv`.
  Identical duplicates are dropped, conflicting labels for the same `image_id` are rejected,
  missing image files are rejected.
- **Retrain (T5.2):** one command. Empty registry → train from scratch; otherwise fine-tune
  from the current model (its backbone config is reused) with fewer epochs and lower LR.
- **Promotion (T5.3):** candidate and current model evaluated on the **same** frozen test split
  of the new dataset; promoted if `candidate_metric ≥ current_metric − tolerance`
  (default: combined QWK, tolerance 0). Optional `promotion.sources: [hospital]` judges only on
  clinical test images. Per-source metrics are always reported.
- **Registry (T5.4):** `models/registry.json` with one `current`, `archived` and `rejected`
  versions, dataset hash, stage, parent, decision text; each version folder keeps the model,
  model card, config, history and `retrain_report.json`.

## Findings / Results
Demo on the laptop GPU (data root `J:/rausnet_data`):

| Version | Data | Decision | Test combined QWK |
|---|---|---|---|
| v0001 | synth (200 patients, 1 200 img), from scratch, 20 epochs | PROMOTED (first model) | 0.908 (198 test img) |
| v0002 | + incoming batch_001 (60 patients, 360 img), fine-tune 10 epochs | **REJECTED** | 0.894 vs current 0.898 (240 test img, 40 patients) |

- The test set grew from 198 to 240 images because new patients hash into it; old test
  patients stayed in test (frozen split verified in practice).
- v0002 vs v0001 differ by 3 of 240 images: statistically indistinguishable. With tolerance 0
  the rule is safe but conservative — it can reject a model trained on more data.
- 73 unit tests pass, including a CPU lifecycle test (promote → promote → reject → no-new-data error).

## Decisions
- Keep tolerance 0 as the safe default for now.

## Proposed improvement (for discussion)
- Replace the fixed tolerance with a **paired bootstrap** over test patients: promote unless
  the 95 % CI of (candidate − current) QWK lies entirely below 0. This also gives CIs for the paper.
