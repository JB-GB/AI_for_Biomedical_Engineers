## Actions
- API:
  - `GET /workspace/status` (only with `--workspace`) wraps `improve.status`. It adds the threshold
    (`min_new_images`, default 20, `--min-new`), `ready`, `served_version` and `new_model`.
  - `POST /model/reload` re-reads the registry and loads the new ONNX model fully before
    switching. If it fails to load, the API answers 409 and keeps serving the previous model.
  - Both endpoints answer 503 when the API serves a fixed `--model-dir`.
- Desktop app: three tabs.
  - **Analizar**: the existing flow, unchanged.
  - **Mejorar el modelo**:
    - global model version and date, with quality in words (QWK as a tooltip);
    - a progress bar and the sentence "n de 20 imágenes nuevas para la próxima mejora";
    - batches still syncing, and any run in progress (taken from the lock);
    - the last 5 runs, in plain words;
    - `Mejorar en Colab` opens the notebook link, and asks to confirm when below the threshold.
  - **Ajustes**: choose the shared folder. It is validated (servable global model), remembered with
    `QSettings`, and switched by starting a new local API and stopping the old one.
- New-model banner `Usar el nuevo modelo`:
  - checked every 2 min and whenever the improvement tab opens;
  - one click reloads the model;
  - the previous result can no longer be exported as PDF, so a report always matches its model.
- Improvement log entries now record `min_new`, so the history can be shown in Spanish.
- Every new button and the progress bar have accessible names (the progress bar speaks the sentence).
