## Actions — continuous improvement
- **Shared workspace** (e.g. a Google Drive folder synced on the hospital PCs): `models/` (global
  registry), `data/incoming/` (new batches + corrections), `data/datasets/`, `improve_log.jsonl`.
- `python -m rausnet.improve run|status|init`:
  - checks the workspace first; fewer than `improve.min_new_images` (20) unseen images → exits in seconds;
  - otherwise stages registry + data on local disk, regenerates the synthetic seed (deterministic,
    never uploaded), runs `retrain` (fine-tune, promotion on the frozen test split, calibration, ONNX);
  - publishes dataset manifest → version folder (copy + rename) → `registry.json` last;
  - exclusive lock (stale after 6 h, for disconnected Colab sessions); batches still syncing are
    reported as incomplete and skipped; empty workspace bootstraps a first model;
  - `init` imports an existing local model and its data without the synthetic images.
- `rausnet-desktop` / `rausnet-api --workspace <folder>` (or `RAUSNET_WORKSPACE`): serve the global model
  and write clinician corrections into the workspace.
- **`notebooks/colab_improve.ipynb`:** opens with a T4 GPU selected; `Run all` + allow Drive. Setup, run,
  numbers-only status, GPU released even if the run fails. "Open in Colab" badge in the README.

## Decisions
- Workspace = plain shared folder (Drive) instead of a server: no infrastructure, works with Colab,
  local GPUs and the runner alike. Readers are protected by publish order, writers by the lock.
- Retrain threshold 20 new images: avoids spending free GPU time on single corrections.
- Interface: stay on PySide6; plan F1–F5 in `docs/06_interface_plan.md` (workspace panel with
  progress "n of 20", `Mejorar en Colab`, new-model banner, accessible single-image flow, SUS).

## Not verified
- The notebook on real Colab (needs a Google account session); Drive FUSE rename/lock semantics there.
- Concurrent writers across machines: Drive does not guarantee atomic exclusive create; the lock is a
  safeguard for normal use, not a distributed lock.
